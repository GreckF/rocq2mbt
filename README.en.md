# rocq2mbt — extraction and interoperability between Rocq and MoonBit

[中文](README.md) | **English**

rocq2mbt has three parts:

1. **An external Rocq plugin** `rocq-mbt.plugin`. It uses the extensible extraction
   API added in Rocq 9.4
   ([rocq-prover/rocq#22541](https://github.com/rocq-prover/rocq/pull/22541), which grew
   out of the discussion in [#22487](https://github.com/rocq-prover/rocq/pull/22487)) to
   register the `MoonBit` extraction language, and adds interop commands
   (`Extract MoonBit Function/Trait/Raise`).
2. **Companion Rocq modules** (`theories/`, logical path `RocqMbt`): extraction of Rocq's
   primitive types (`PrimInt63`/`PrimFloat`/`PrimArray`/`PrimString`), MoonBit's builtin
   types and traits.
3. **MoonBit tools** (`mbt/`): the runtime package `rocqrt`, and `mbti2rocq`, which turns
   a `.mbti` interface into Rocq axioms; on extraction those axioms become calls to the
   original MoonBit package.

```coq
From RocqMbt Require Import Prelude.     (* or MoonBit / ExtrMoonBitBasic / ExtrMoonBitPrim *)
Extraction "pkg/out.mbt" my_function.
```

**The full installation and usage guide is in [docs/USAGE.en.md](docs/USAGE.en.md)**:
installation steps, three runnable quick-start examples, a reference for every module and
command, and troubleshooting.

## Environment

- Rocq: `9.4+alpha`, i.e. the development version on rocq master. Note that the git tag
  `V9.4+alpha` (2026-06-29) **predates** the merge of the extraction plugin API
  (2026-10-05), so `scripts/setup-opam.sh` pins a master commit that contains the API.
- opam: a project-local switch. When the project lives on `/mnt/c`, the switch is actually
  kept in `~/.local/share/rocq2mbt/_opam` (building on the 9p file system is too slow), and
  `_opam` in the project root is a symlink to it.
- MoonBit toolchain: `~/.moon/bin` (moonc v0.10.20, 2026-11-05; also tested on v0.10.8).
  `mbti2rocq` depends on `moonbitlang/x@0.5.7`.

```bash
bash scripts/setup-opam.sh   # once: create the switch, install OCaml 5.4.1 + rocq-runtime/rocq-core (dev)
source scripts/env.sh        # enter the local switch
dune build                   # build the plugin and theories/
bash tests/run.sh            # all tests (see below)
```

Using the plugin without installing it:
`OCAMLPATH=$PWD/_build/install/default/lib rocq c -Q _build/default/theories RocqMbt foo.v`.

| --- | --- |

| `src/mbt_table.ml` | Tables of the interop commands (libobjects, persisted through `Require`) |
| `src/g_moonbit.mlg` | Plugin declaration, language registration, `Extract MoonBit ...` commands |

| `theories/ExtrMoonBitBasic.v` | `bool/sumbool → Bool`, `option → Option`, `unit → Unit`, `prod → tuples` |

| `theories/Prelude.v` | `Result`, MoonBit builtin types (`Int`, `String`, `Array`, ...), trait classes `Eq/Compare/Show/Hash` and instances |

| `tests/*.v` | Extraction tests, written to `tests/moon/<pkg>/` |
| `tests/moon/` | MoonBit test module (`moon.work` brings in `rocqrt`); `mlib` is the interop sample library |
| `tests/gen/Mlib.v` | Generated by `mbti2rocq` from `tests/moon/mlib` (regenerated by the tests) |

## Extraction: translation scheme

| Rocq / MiniML | MoonBit |
| --- | --- |
| Inductive types | `pub(all) enum T[A, B] { C(A, T[A, B]) }`; constructors are always qualified, `T::C(..)` |
| Records | Single-constructor enum; projections are ordinary functions (match) |
| Singleton inductives / type definitions | `pub type T[A] = ...`; expanded at use sites if the right-hand side is a type variable (forbidden in MoonBit) |
| Coinductive type `T` | `enum TCell` + `pub type T = RocqLazy[TCell]`; built with `rocq_lazy(fn() {..})`, forced with `rocq_force` before matching |
| Type variables | Named by position `A, B, ...`, skipping letters that clash with type names in the file |
| Top-level functions | **Uncurried**: `n` = min(number of leading λs, number of arrows in the type), `pub fn f(x : A, y : B) -> C` |
| Calls | With ≥ n arguments, a direct call; with fewer, non-trivial arguments are `let`-bound first (evaluated once), then eta-expanded into curried closures; references as values are eta-expanded too |
| Function-typed values | Always one-argument closures `(A) -> (B) -> C` |
| Polymorphic constants / non-function fixpoints | Zero-argument generic functions `pub fn[A] c() -> List[A]`, referenced as `c()` |
| Monomorphic constants | `pub let c : T = ...` |
| Local `fix` | `letrec f = fn(x) {..} and g = ..`; local cofixpoints with a non-function body become `fn() {..}` |
| `let ... in` | Blocks `{ let x = ..; .. }` (consecutive lets are flattened) |
| `Obj.magic` | `rocq_magic` (`"%identity"`), see limitations |
| Types that cannot be expressed | `RocqAny` |
| Erased logical parts | `Unit` / `()` |
| Impossible branches, unrealized axioms | `abort("...")` |
| Primitive literals | `42UL` (int63), `0x1.8p3` / `(0.0 / 0.0)` (float), `@rocqrt.PArray::of_array([..], def)` (array), string literals |

### Custom extraction

- `Extract Constant c => "e"`: `e` is a MoonBit expression of the **curried extracted type**.
- `Extract Inductive t => "Ty" [ "c1" "c2" ] "m"`: constructor strings are applied like
  functions when building values (`c2(x, y)`) and used as patterns when matching; a string
  containing `$i` is a template (e.g. `"@pkg.Shape::Rect(w=$0, h=$1)"`). The optional match
  function `m` is called as `m(fn(..) { branch1 }, ..., scrutinee)`, with **uncurried**
  branch functions. `"(,)"` stands for MoonBit tuples.

### Interop commands (added by this plugin)

| Command | Effect |
| --- | --- |
| `Extract MoonBit Function f [n] => "tpl".` | Realizes `f` with a call template: `$i` is the i-th non-dictionary argument, `n` (default: number of placeholders) is the number of arguments consumed. Saturated calls expand the template, partial applications are eta-expanded, arguments are bound first when the template contains a closure or repeats a placeholder |
| `Extract MoonBit Trait C => "@pkg.Trait".` | The class (record) `C` is the dictionary type of a MoonBit trait: dictionary arguments of type `C` are dropped when calling external functions (MoonBit dispatches statically), and generic functions with a `C A` parameter get the bound `A : Trait` |
| `Extract MoonBit Raise f.` | The Rocq function `f : .. -> Result T E` is extracted as `-> T raise E`; call sites convert back to `Result` with `try ... catch ... noraise`; if `E` is a Rocq inductive type it is printed as a `suberror` |

## Companion Rocq modules

- **`ExtrMoonBitPrim`**: Rocq's primitive 63-bit integers are represented as `UInt64`
  (values kept below 2^63; signed operations use bit 62 as the sign bit); `float` is
  `Double`; `PrimArray.array` is `@rocqrt.PArray` (Baker diff arrays: O(1) for linear use,
  rerooting when an old version is accessed). The semantics follow the Rocq kernel's
  `uint63_63.ml` / `float64_common.ml` / `parray.ml` operation by operation.
  `comparison`, `carry`, `float_class` and `float_comparison` map to enums in `@rocqrt`.
- **`Prelude`** (includes the two modules above): `Result` (MoonBit's `Result`); builtin types
  `Int Int64 UInt UInt64 Byte Char String Bytes Error Array`, `Double := float`;
  conversions (`Int_of_uint63`, ...), `Int` arithmetic, `String`, purely functional `Array`
  operations; trait classes `Eq Compare Show Hash` with instances for the builtin types
  (instance methods all use generic axioms such as `Builtin.equal`, which dispatch
  statically after extraction, at a concrete type or under a bound).

The extracted MoonBit package must `import { "rocq2mbt/rocqrt" @rocqrt }` in its `moon.pkg`,
and its module must depend on `rocq2mbt/rocqrt` (this repository uses `moon.work`).

## mbti2rocq

```bash
cd mbt/mbti2rocq && moon build --target native --release
_build/native/release/build/cmd/main/main.exe path/pkg.generated.mbti -o Pkg.v [--alias @pkg]
```

Translates an interface produced by `moon info` into a Rocq file built on
`From RocqMbt Require Import Prelude.`:

| MoonBit | Rocq |
| --- | --- |
| `pub fn f(A, B) -> C` | `Axiom f : A -> B -> C.` + `Extract MoonBit Function f => "@pkg.f($0, $1)".` |
| Method `fn T::m(Self, ..)` | `T_m`, template `@pkg.T::m(..)` |
| Zero-argument functions | `unit -> R` (delays side effects) |
| Labelled `x~ : T` / optional `x? : T` parameters | Positional, template writes `x=$i` / omitted (default value used) |
| `fn[A : Eq] ..` | `forall {A : Type} `{Eq A}, ..` |
| `-> T raise E` | `-> Result T E`, template wrapped in `try ... catch ... noraise` |
| Multi-parameter function types `(A, B) -> C` | Curried `A -> B -> C`, converted in both directions in the template (parameters and results) |
| `pub(all) enum` / `suberror` | `Inductive` + `Extract Inductive` (templates for labelled constructors) |
| `pub(all) struct` (≥ 2 fields, no `mut`) | `Record` + `Extract Inductive` (construction template + custom match) |
| Other types (private fields, `mut`, single-field / single-constructor wrappers, recursion that is not strictly positive) | `Axiom T : Type.` + field getter / constructor / destructor axioms |
| `pub let` / `pub const` | `Axiom` + template `@pkg.x` |
| `trait T { m(Self) -> X }` | `Class T (Self : Type) := { m : Self -> X }.` + `Extract MoonBit Trait` + generic method axioms |
| `impl T for X` | `#[global] Instance T_X : T X.` (Prelude traits use `Builtin.*`) |
| Types of other packages, `@json.Json` etc. | `Axiom json_Json : Type.` + extraction directive, generated automatically |

Declarations that cannot be translated (`async`, `&Trait`, unknown trait bounds,
multi-parameter functions inside containers, tuples of 3 or more elements, ...) are skipped,
with the reason in a comment at the end of the generated file. The files generated for
core's `@math`/`@list`/`@json` have been checked to compile in Rocq.

## Limitations

- **`rocq_magic` only works on backends with a uniform value representation**: tested to work
  with `--target wasm`; wasm-gc fails to compile and native segfaults (js untested). The
  plugin warns when it is needed.
- Only monolithic (single-file) extraction. `Separate Extraction`/`Extraction Library` fail.
- Modules are flattened and clashing names are renamed (e.g. `k`, `k0`); unapplied functors
  are omitted.
- MoonBit local closures have no let-polymorphism.
- Bridging trait dictionaries with MoonBit's static dispatch: instances written by the user in
  Rocq are only used through their dictionaries in Rocq code; when a value is passed to an
  external MoonBit function, MoonBit uses the type's own `impl` (this first version does not
  generate MoonBit `impl`s for Rocq instances).
- `PrimString` only maps the type and literals (Rocq strings are byte strings, MoonBit
  strings are UTF-16).

## Tests

`bash tests/run.sh`: `rocqrt` unit tests (5 groups); `basic`(4) / `advanced`(6) /
`prim`(5) / `interop`(5) pass on wasm-gc, wasm and native; `magic`(1) passes on wasm.
`interop` is the full pipeline: `tests/moon/mlib` → `moon info` → `mbti2rocq` →
`tests/gen/Mlib.v` → called from `tests/Interop.v` → extraction → run in `tests/moon/interop`.
